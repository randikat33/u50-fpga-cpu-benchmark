# 10_Heston_Accuracy — paper 2: energy to a target accuracy

Single-asset Heston European call (strikes 70, 100, 140), two schemes:

- **FT**: Euler with full truncation (Lord et al. 2010).
- **QE**: Andersen's (2008) quadratic-exponential scheme, ψc = 1.5, γ1 = γ2 = ½, no martingale correction.

Test cases I, II, III (Andersen 2008) and P1 (paper 1's parameters on one asset), as in the protocol (`paper2/protocol_v0.3.md`).

Phase 2 (calibration, CPU only) is done. Phase 3 added the FPGA kernels (both built at 225 MHz), the FPGA host, the AVX-512 code and the CPU-native code; the secondary cases follow.

## Numerics (what must stay identical on every platform)

- Two random words per time step, shared by the two antithetic paths:
  - FT: two normals.
  - QE: one uniform for the variance (via the inverse CDF in the quadratic branch, and ln(1−U) in the exponential branch) and one normal for the log-price.
- **Log-price and FT variance are summed as exact integers:**
  - log-price: X = X0 + Xi·2⁻⁴⁰;
  - FT variance: U = Ui·2⁻⁵⁸.

  A float sum rounded in the same direction step after step: it biased the QE price by 7×10⁻⁵ (relative) in Case I. The integer sum removed this (float minus double: 3×10⁻⁶ instead of 9.7×10⁻⁴).
- **QE's logarithm** is a fixed-point table method: a 1,024-entry table plus a second-order term, with an absolute error below 6×10⁻¹⁰. This keeps the card and the CPU bit-identical.
- **Payoffs** are exact integer multiples of 2⁻¹⁶, and the moments are 128-bit integer sums. The result therefore does not depend on how the pairs are split across threads or batches (tested).
- **Call or put payoff per strike (protocol v0.4).** Each strike is priced from the payoff form with the smaller variance among the forms with finite variance; a put gives the call by put-call parity, C = P + S₀ − K e^(−rT). The call payoff has infinite variance in Case II (Heston moment explosion: E[S_T²] = ∞ for T > 13.2 years). Puts: Case I K = 70; Case II all; Case III all; P1 K = 70 (`hq::Case::puts`, `fp[P_PUTS]`; the kernel gets the mask as a seventh settle word). The put form is −(S − K), an exact negation, so all programs stay bit-identical; `test_units` checks parity path by path.

## Secondary cases (protocol v0.5, Section 4b)

Registered on 15 October 2026 (commit d16fe83), after the main-case measurements. The main-case code above is unchanged; the secondary cases have their own files.

- **Case B**, paper 1's 8-asset Heston basket (independent assets, Feller satisfied), strikes 90, 100, 110, FT and QE. Each asset of a basket pair is simulated exactly like a single-asset pair of `hq_model.hpp` (unit 8a + j, its own stream). The 8 prices at maturity are quantised to 2^-32 and summed as exact integers, so the sum does not depend on the order.
- **Case A**, arithmetic Asian call under Black–Scholes, 250 daily dates, strikes 90, 100, 110. The plain and control-variate (geometric Asian, Kemna–Vorst) estimators come from the same paths. The log-price is an exact int64 sum, and the price sum is quantised to 2^-24. β is fixed per strike from the calibration (`results/beta_A.csv`).
